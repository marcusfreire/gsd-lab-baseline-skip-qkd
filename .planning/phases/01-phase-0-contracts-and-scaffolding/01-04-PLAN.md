Decision coverage:
- D-04: baseline uses two separate KME simulator instances: `KME-A` and `KME-B`.
- D-05: `KME-A` owns the local KME endpoint and storage for `SAE-A`.
- D-06: `KME-B` owns the local KME endpoint and storage for `SAE-B`.
- D-07: KME simulator implementation is sourced from `kms/`.
- D-08: KME-A and KME-B must not be collapsed into one central KME.
- D-09: KME-A and KME-B must not rely on shared KME storage for normal operation.
- D-10: `KeyProvider-A` acts as `SAE-A` when calling `KME-A`.
- D-11: `KeyProvider-B` acts as `SAE-B` when calling `KME-B`.
- D-12: KeyProvider-A consults only KME-A; KeyProvider-B consults only KME-B.
- D-13: KeyProvider-A and KeyProvider-B have separate provider state and SQLite databases.
- D-14: there is no central shared database between Key Providers.
- D-39: Compose defines separate `kme-a`, `kme-b`, `keyprovider-a`, `keyprovider-b`, `encryptor-a-sim`, and `encryptor-b-sim` services.
- D-40: KME and Key Provider storage use separate volumes or database paths for A and B.
- D-41: Phase 0 uses placeholder commands and service directories while exposing future component boundaries.
- D-44: Phase 0 does not require containers to start or provide working service logic.

<threat_model>
Scope: local Docker Compose skeleton and placeholder service directories; containers are not required to start and no full service logic is created.

Assets:
- Provider independence in runtime configuration.
- Correct KME-A/KME-B topology based on `kms/`.
- Avoidance of accidental production claims in scaffold.

Threats and mitigations:
- HIGH: Compose collapses the two KME sides into one central service. Mitigate by requiring separate `kme-a` and `kme-b` services with separate state paths or volumes.
- HIGH: Compose introduces shared Key Provider state. Mitigate by requiring separate provider volumes or SQLite paths and rejecting central provider database services.
- MEDIUM: A project-local `services/kme-mock/` scaffold competes with `kms/`. Mitigate by documenting that KME-A/B come from `kms/` and creating only Key Provider/encryptor service scaffolds under `services/`.
- MEDIUM: Placeholder commands look like real services. Mitigate with explicit placeholder text in Compose and service READMEs stating that Phase 0 does not implement API logic.
- LOW: Compose parse check fails because scaffold directories are missing. Mitigate by creating required README placeholders before verification.

Blockers: HIGH shared-state and one-KME threats are mitigated by concrete service and volume acceptance criteria.
</threat_model>
