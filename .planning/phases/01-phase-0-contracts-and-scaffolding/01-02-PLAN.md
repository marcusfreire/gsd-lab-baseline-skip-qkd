- `docs/api-etsi014-mock.md` - minimal logical ETSI GS QKD 014 mock API contract.
- `docs/api-skip.md` - SKIP API contract pinned to `draft-singh-skip-00`.
- `docs/data-model.md` - identifier, key material, and provider-state model.
- Concepts documented: `qkd_key_id`, ETSI `key_ID`, SKIP `keyId`, `skip_key_id`, `SKIP_KEY_ID_NAMESPACE_SECRET`, provider-local SQLite state, keyId collision behavior.

Decision coverage:
- D-04: protocol docs use endpoint matrices plus JSON examples with methods, paths, fields, status behavior, authority, and examples.
- D-05: `docs/api-skip.md` is strict against `draft-singh-skip-00`.
- D-06: `docs/api-etsi014-mock.md` is strict only inside the declared minimal ETSI 014 mock profile and lists deviations from full ETSI GS QKD 014.
- D-10: SKIP `keyId` derives from `qkd_key_id`, `localSystemID`, and `remoteSystemID` with HMAC-SHA256, truncated to 16 bytes and lowercase hex encoded.
- D-11: `SKIP_KEY_ID_NAMESPACE_SECRET` is shared by KeyProvider-A and KeyProvider-B, is not QKD key material, and exists only to make deterministic IDs compatible.
- D-12: SKIP `keyId` uniqueness is required; collisions fail, are recorded/reported, and never overwrite existing key material.

<threat_model>
Scope: Documentation contracts for future APIs and data handling; no running endpoint or persistence logic is introduced by this plan.

Assets:
- Correctness of SKIP contract against `draft-singh-skip-00`.
- Correctness of the declared minimal ETSI 014 mock profile.
- Separation of identifier domains and simulated key material.

Threats and mitigations:
- HIGH: SKIP documentation drifts into a SKIP-like API instead of `draft-singh-skip-00`. Mitigate by explicitly naming the draft, documenting the required methods and fields, and listing status behavior for unsupported paths and methods.
- MEDIUM: ETSI mock documentation over-claims full ETSI GS QKD 014 conformance. Mitigate by adding a `Deviations from full ETSI GS QKD 014` section with local HTTP, no mTLS, no physical QKD, and logical key availability only.
- MEDIUM: Identifier domains collapse into one ambiguous field. Mitigate by documenting `qkd_key_id`, ETSI `key_ID`, SKIP `keyId`, `skip_key_id`, and `key_material` separately.
- MEDIUM: Deterministic keyId derivation leaks key material or is delimiter-ambiguous. Mitigate by deriving only from identifiers with HMAC-SHA256 and by specifying length-prefixed UTF-8 input encoding.

Blockers: The HIGH SKIP drift threat is mitigated in-plan by exact draft pinning and endpoint matrix acceptance criteria.
</threat_model>
