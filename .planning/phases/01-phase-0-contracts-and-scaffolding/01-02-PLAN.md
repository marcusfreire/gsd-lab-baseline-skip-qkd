Decision coverage:
- D-15: public ETSI API preserves supported `status`, `enc_keys`, and `dec_keys` routes and methods.
- D-16: public ETSI JSON names preserve `source_KME_ID`, `target_KME_ID`, `master_SAE_ID`, `slave_SAE_ID`, `key_ID`, and `key_IDs`.
- D-17: ETSI key material is base64 and Key Providers convert ETSI base64 to bytes then SKIP hex.
- D-18: `docs/api-etsi014-mock.md` is strict only within the declared minimal ETSI 014 profile and lists deviations.
- D-19: SAE/KME topology is an authorization policy, not a naming convenience.
- D-20: in mTLS mode, caller SAE identity comes from the client certificate Common Name.
- D-21: in local HTTP mode, `x-sae-id` is valid only when mTLS is disabled.
- D-22: unknown caller/peer SAE, wrong master, wrong slave, and wrong ownership reject before key release.
- D-23: `enc_keys` stores or emits records with `master_sae_id`, `slave_sae_id`, `key_ID`, key bytes, and availability state.
- D-24: `dec_keys` verifies caller slave SAE, path master SAE, requested `key_ID`, and availability.
- D-25: successful `dec_keys` consumes the key so repeat retrieval fails.
- D-26: `docs/api-skip.md` is strict against `draft-singh-skip-00`.
- D-27: SKIP fields use draft names including `localSystemID`, `remoteSystemID`, `keyId`, and `key`.
- D-28: SKIP key material is hexadecimal.
- D-29: SKIP key ID is deterministic and textual: `skip_key_id = "SKIP-" + master_SAE_ID + "-" + slave_SAE_ID + "-" + key_ID`.
- D-30: example mapping is `QKD-000001`, `SAE-A`, `SAE-B` -> `SKIP-SAE-A-SAE-B-QKD-000001`.
- D-31: SKIP key ID must not reveal key material.
- D-32: responder maps `SKIP-SAE-A-SAE-B-QKD-000001` back to ETSI `key_ID` `QKD-000001` before `dec_keys`.

<threat_model>
Scope: documentation contracts for future APIs and data handling; no endpoint or persistence logic is introduced.

Assets:
- Correctness of the SKIP contract against `draft-singh-skip-00`.
- Fidelity of the supported ETSI 014 subset.
- Separation of identifier domains and simulated key material encodings.

Threats and mitigations:
- HIGH: SKIP documentation drifts into ad hoc endpoint or field names. Mitigate by requiring draft-pinned endpoint and field matrices with `localSystemID`, `remoteSystemID`, `keyId`, and `key`.
- HIGH: ETSI documentation changes public names such as `key_ID` or `key_IDs`. Mitigate by requiring source checks for all public ETSI names and supported `status`, `enc_keys`, and `dec_keys` routes.
- MEDIUM: Docs imply full ETSI GS QKD 014 conformance. Mitigate with a deviations section and minimal-profile language.
- MEDIUM: Key material encoding is ambiguous. Mitigate by documenting ETSI base64, SKIP hex, and the exact conversion path.
- MEDIUM: `skip_key_id` is mistaken for a secret. Mitigate by stating it is deterministic metadata and must not reveal key material.

Blockers: HIGH threats are mitigated by exact field and route acceptance criteria.
</threat_model>
