- D-01: `README.md`, `docs/*.md`, `infra/docker-compose.yml`, and `AGENTS.md` are the normative Phase 0 contracts.
- D-02: `baseline.md`, if present, is historical context only after the Phase 0 baseline exists.

- D-04: the baseline uses two separate KME simulator instances, `KME-A` and `KME-B`.
- D-05: `KME-A` owns the local KME endpoint and storage for `SAE-A`.
- D-06: `KME-B` owns the local KME endpoint and storage for `SAE-B`.
- D-07: KME simulator implementation is sourced from `kms/`.
- D-08: KME-A and KME-B must not be collapsed into one central KME.
- D-09: KME-A and KME-B must not rely on shared KME storage for normal operation.
- D-10: `KeyProvider-A` acts as `SAE-A` when calling `KME-A`.
- D-11: `KeyProvider-B` acts as `SAE-B` when calling `KME-B`.
- D-12: KeyProvider-A consults only KME-A; KeyProvider-B consults only KME-B.
- D-13: KeyProvider-A and KeyProvider-B have separate provider state and SQLite databases.
- D-14: there is no central shared database between Key Providers.
- D-33: KeyProvider-A gets outbound key material from KME-A with `enc_keys`.
- D-34: Encryptor-A obtains SKIP `{ keyId, key }` from KeyProvider-A.
- D-35: Encryptor-A hands `keyId` to Encryptor-B through simulated handoff.
- D-36: Encryptor-B requests `GET /key/{keyId}?remoteSystemID=Alice` from KeyProvider-B.
- D-37: KeyProvider-B resolves SKIP `keyId`, calls KME-B `dec_keys`, and returns matching SKIP hex.
- D-38: the required e2e invariant is `key_hex_alice == key_hex_bob`.
- D-42: Phase 0 acceptance is based on required docs, internal consistency, scaffold directories, and parseable Compose when available.
